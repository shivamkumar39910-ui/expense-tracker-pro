## 1. AUTHENTICATION & CREDENTIAL SECURITY

### 1.1 Password Hashing
- **Algorithm:** PBKDF2 with SHA-256 via Werkzeug Security.
- **Salt:** Cryptographically secure unique salt per user generated by OS entropy (`os.urandom`).
- **Storage:** No plaintext passwords exist anywhere in the application, memory logs, or database.

### 1.2 Two-Factor Authentication (2FA) & One-Time Passwords (OTP)
- **Generation:** 6-digit random integers generated using Python's `secrets` module (cryptographically strong pseudo-random number generator).
- **Time-to-Live (TTL):** Hard expiry enforced at 10 minutes (`datetime.now(timezone.utc) + timedelta(minutes=10)`).
- **One-Time Consumption:** After a successful verification, the stored OTP code and expiration timestamp are immediately wiped (`NULL` in database).

### 1.3 App Security PIN
- **Algorithm:** Salted SHA-256 hash.
- **Validation:** Enforces strictly 4 decimal digits (`^\d{4}$`).
- **Brute-Force Rate Limiting:** After 5 consecutive incorrect PIN attempts, the user account is locked for 15 minutes, returning HTTP 429 Too Many Requests.

## 2. SESSION & JWT INTEGRITY

- **Token Type:** JSON Web Token (JWT) signed via HS256 algorithm.
- **Payload Claims:**
  - `user_id`: Integer primary key of authenticated user.
  - `email`: User registered identifier.
  - `iat`: Issued At timestamp.
  - `exp`: Expiration timestamp (hard limit: 7 days).
- **Token Verification:** Every protected endpoint invokes `@token_required`, validating signature, expiration, and user existence before executing business logic.

---

## 3. MULTI-TENANT DATA ISOLATION & SQL INJECTION RESILIENCE

### 3.1 Strict Parameterized Queries
- **100% Parameterization:** Zero string formatting (`f"..."` or `%s` interpolation) for user inputs.
- **Dual-Dialect Translation:** `db_engine.py` converts `?` to `%s` parameters cleanly passed directly to psycopg2's C-level driver, eliminating SQL injection vectors.

### 3.2 Tenant Isolation Guarantee
- **Mandatory User ID Scoping:** Every single query in the application includes `WHERE user_id = %s` derived exclusively from the verified JWT claim (never from client request parameters).
- **Foreign Key Cascading:** Deleting a user safely cascades to delete all associated accounts, transactions, budgets, goals, and notification logs without orphaned data.

---

## 4. HTTP SECURITY HEADERS & DEFENSE-IN-DEPTH

The Flask application enforces the following HTTP response headers globally:
- `X-Content-Type-Options: nosniff` (Prevents MIME-sniffing attacks)
- `X-Frame-Options: SAMEORIGIN` (Mitigates clickjacking attacks)
- `X-XSS-Protection: 1; mode=block` (Reflected XSS filter)
- `Content-Security-Policy`: Restricts script and asset execution to trusted domains.
- `Access-Control-Allow-Origin`: Explicitly configured via Flask-CORS to prevent unauthorized cross-origin requests.
